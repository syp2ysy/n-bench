World Action Model 领域综述：从反应式 VLA 到动作-未来联合建模

摘要

World Action Model，简称 WAM，正在把 embodied AI 中两个原本分离的方向重新接到一起：一端是 Vision-Language-Action 模型把观测和语言指令直接映射到动作，另一端是 world model 预测环境未来、供规划器或策略使用。成熟的 WAM 综述不应只问系统里有哪些模块，而要先回答领域读者最关心的几个问题：WAM 和 VLA、world model、action-conditioned video model、video policy 的边界在哪里；主流 architecture 是先预测未来再行动，还是在统一序列中共同建模动作和世界；训练数据从机器人遥操作、仿真、human demonstrations 到互联网视频各自贡献什么；评测到底在测视觉真实感、物理常识、动作合理性、策略收益还是部署代价。本文因此采用 community-native WAM survey 作为文章主线，以 Cascaded WAM 和 Joint WAM 作为一级 taxonomy，把七类系统接口降为横向诊断 lens，用来解释 representation、dynamics/update、action decoding、controller interface、memory/retrieval 和 uncertainty/evaluator 如何改变架构取舍。

本文的核心判断是：WAM 不是“更大的 VLA”，也不是“会看动作的视频生成器”。它是一类把 action 和 future representation 纳入同一学习、推理或训练闭环的模型族。Cascaded WAM 强调显式未来、显式 rollout 或显式辅助世界模型；Joint WAM 强调动作 token、视觉 token、语言 token 或 latent token 的统一建模。两者并非优劣二分，而是在可解释性、延迟、数据需求、误差传播和控制接口之间做不同交换。这个框架能把 Deep Visual Foresight、latent imagination、VLA action tokenization、Unified Video Action Model、WorldVLA、Fast-WAM、object-addressable WAM、memory-augmented WAM 和新近评测基准放到同一张图里讨论，而不是把论文排成时间线。

1. Introduction: from reactive VLA to WAM

机器人基础模型的第一波扩展主要发生在 reaction side：给定当前图像、语言指令和少量历史，模型输出低层动作、离散 action token 或 flow action。RT-1、RT-2、Open X-Embodiment、Octo、OpenVLA、pi0 和 FAST 这条线把网络规模、跨机器人数据、语言监督与动作 tokenization 带进了真实机器人控制 [p016] [p019] [p021]。它的优势是端到端，部署路径清晰；限制是模型内部不一定显式表达“动作之后世界会变成什么”。当任务需要接触后物体状态、遮挡后的持久性、长程子目标、可逆与不可逆操作、以及失败前的预演时，纯反应式策略容易把未来压缩成一个动作分布，而不是可检查、可修正的中间对象。

world model 传统提供了另一条路线。World Models、PlaNet、Dreamer、DreamerV3 与 TD-MPC 类方法把 latent dynamics、reward/value 或 imagined rollout 放在控制中心 [p001] [p003]。Deep Visual Foresight 则更早展示了 action-conditioned video prediction 如何服务 robot motion planning [p008]。这些方法的共同点是：未来不是隐含在 action logits 里的副产物，而是策略可以查询、采样、比较或训练的对象。问题在于，经典 world model 多半面向强化学习或特定连续控制，和大规模 VLA 的语言、开放类别视觉、跨 embodiment 数据并未自然合流。

WAM 的出现正是这个裂缝的结果。它试图让 action model 不只是“当前观测到动作”的映射，也让 world model 不只是“无动作视频”或“控制用 latent dynamics”。Unified Video Action Model 直接把 video 和 action 放在统一模型中处理，WorldVLA 以 autoregressive action-world modeling 方式把动作和世界 token 串接起来，Fast-WAM 反过来追问 test-time future imagination 是否总是必要，GigaWorld-Policy 和 MotuBrain 则把效率、训练规模和机器人控制接口推到更靠近部署的位置 [p022] [p023] [p026] [p027] [p028]。这些工作共享一个领域问题：模型如何在观察、语言、动作和可预测未来之间建立可训练、可评测、可部署的接口。

因此，本综述不再把 WAM 拆成主目录中的“七个系统节点”。那种 system-node 视角有助于做接口审计，但它不是领域原生的文章 spine。更合适的主线是先定义 WAM，再回到 world model、VLA、video generation 和 action model 背景，随后以 Cascaded WAM 与 Joint WAM 组织 architecture taxonomy，再单独讨论 training data ecosystem 与 evaluation protocols。系统接口在第 7 节作为 cross-cutting diagnostic lens 返回，用来解释同一架构家族内部为何会出现不同表示、动作接口、记忆和 uncertainty 设计。由此，读者先得到一张领域地图，再得到可用于读论文和做系统设计的诊断工具。

2. Definition and formalism: WAM, VLA, world model, ACWM, video policy

一个工作性的定义是：WAM 学习从历史观测、语言或任务条件、候选动作或动作历史到未来世界表示与动作决策之间的联合关系。形式上，可以把输入写成 $h_t=(o_{1:t}, l, a_{1:t-1})$，模型学习 $p(z_{t+1:t+H}, a_{t:t+H} | h_t)$、$p(z_{t+1:t+H} | h_t, a_{t:t+H})$，或一个可用于策略训练的 latent consistency objective。这里的 $z$ 可以是像素视频、latent embedding、object-centric state、joint token stream 或可供 controller 使用的 imagined feature。关键不在于一定输出视频，而在于 action 与 future representation 同时进入模型的学习或推理闭环。

这个定义把 WAM 和几个相邻概念区分开。VLA 模型通常学习 $p(a_t | o_t, l, h_t)$，也可以有 action chunking、flow matching 或 tokenization，但 future state 不一定是显式训练目标 [p019] [p021]。classic world model 学习 dynamics，可用于 planning 或 imagination，但未必接入大规模 language-conditioned robot policy，也未必把 action-world alignment 做成统一序列 [p001] [p003]。Action-conditioned world model，或 ACWM，更强调给定 action 后预测未来视觉或物理交互；WAM 则把这种预测和 action synthesis、policy utility、training data scaling 合并到一个机器人基础模型问题中 [p038]。Video policy 可能直接从视频表示中产生动作，但如果未来生成只作为预训练素材而不进入动作-未来一致性约束，它仍未必构成严格意义上的 WAM。

这个边界还可以从反例看得更清楚。一个 VLA 若只把大规模视觉语言知识转化为动作输出，它可以是优秀的 robot policy，但还不是完整 WAM；一个 video foundation model 若能生成长视频，却没有 action conditioning 或 policy utility 连接，它是 world prior 而不是 WAM；一个 model-based RL 系统若只在低维状态上做 reward-oriented planning，却没有开放视觉、语言或机器人动作接口，它是 WAM 的祖先而非当前 embodied WAM 的全部形态。WAM 作为术语的价值，正在于把这些相邻能力重新组合成 action-future-policy 三角关系。

定义上的困难来自三个维度。第一，future representation 的粒度不同：像素视频适合人类检查和物理常识评测，latent future 适合低延迟控制，object-addressable state 适合 manipulation 中的持久物体关系 [p030] [p031]。第二，action interface 的形式不同：连续动作、离散 action token、语言化动作、skill token、flow action 和 autoregressive token stream 会改变模型能否做 long-horizon consistency [p020] [p021] [p023]。第三，WAM 可以用于 inference-time planning，也可以只在 training-time shaping policy；Fast-WAM 把这个区别推到中心，因为如果未来 imagination 只在训练阶段提供约束，部署时可以获得更低延迟 [p026]。

因此，本文把 WAM 的必要条件设为三条：一是模型显式接收、生成、对齐或使用 action；二是模型学习某种 future/world representation，而非只输出即时动作；三是 action 和 future 的关系会改变策略、训练信号、评测协议或部署行为。满足三条的工作可以落入 Cascaded 或 Joint taxonomy；只满足其中一两条的工作则作为 background、bridge 或 boundary case 讨论。这个定义避免把所有 VLA 都泛化成 WAM，也避免把所有视频生成模型都纳入 WAM。

这个定义也决定了综述写法。定义章节不能只给一句宽泛描述，而要为后续 taxonomy 设置判别规则：当一篇论文强调未来视频再规划，它应进入 Cascaded WAM；当它强调动作 token 与世界 token 的统一生成，它应进入 Joint WAM；当它只提供数据、benchmark、VLA action representation 或 world prior，它应作为 support layer 或 boundary case。这样的 formalism 能让读者在遇到新论文时判断其位置，而不是被论文标题中的 “world action” 或 “video action” 牵着走。

3. Background: world models, VLA, video generation, action models

WAM 的第一条背景线是 latent world model。早期工作把视觉观测压缩进 latent state，通过 recurrent dynamics 或 stochastic latent transition 预测未来，再在 imagined trajectories 上训练 actor-critic。World Models 和 Dreamer 系列让“在模型内部想象未来再控制”成为清晰范式 [p001] [p003]。这条线给 WAM 留下两个遗产：future representation 可以不必是像素，且 world model 的价值最终要通过 control utility 而不只是 prediction loss 来判断。

第二条背景线是 visual foresight 和 action-conditioned video prediction。Deep Visual Foresight 以 action-conditioned video prediction 为 planning substrate，体现了 Cascaded WAM 的雏形：给定候选动作，预测未来图像，再选择符合目标的动作 [p008]。Genie 和 iVideoGPT 把 interactive generative environments 推向更大规模，说明视频模型可以获得某些可交互 dynamics 结构，但也提醒我们：可生成并不等于可控制，video fidelity 和 policy utility 之间需要评测桥接 [p009] [p010]。

第三条背景线是 VLA 和 robot foundation models。Open X-Embodiment 提供跨机器人数据和 RT-X 模型，Octo、OpenVLA、pi0 和 FAST 推动通用 policy、open-source VLA、flow action 和 action tokenization [p016] [p019] [p021]。这条线的贡献是让 action interface 变成可规模化的语言-视觉-控制问题。它的缺口是：policy 的动作输出不一定伴随未来状态可解释性，benchmarks 也常把 success rate 当成汇总指标，难以区分未来理解、动作可行性和控制器鲁棒性。

第四条背景线是 physical AI world foundation model 和 embodied benchmark。Cosmos、V-JEPA 2、WorldArena、SC3-Eval 和 ACWM-Phys 代表了从大规模视频预训练、self-supervised predictive representations 到 embodied utility evaluation 的迁移 [p011] [p012] [p036] [p037] [p038]。这些工作对 WAM 的意义不是“背景材料”，而是约束 WAM 必须回答的评测问题：一个模型看起来能生成物理合理视频，是否能让 policy 更好；一个模型在 perception benchmark 上好，是否能转化为 functional utility；一个 action-conditioned video model 的物理交互能力如何被隔离测量。

由此可见，WAM 不是凭空出现的术语，而是四条技术线的交汇：latent imagination 提供未来表征，visual foresight 提供 action-conditioned prediction，VLA 提供语言与动作接口，world/video foundation models 提供数据与 scaling。成熟综述需要把这四条线合成一个 taxonomy，而不是把每篇论文分别归入一个组件箱。

从方法演化看，WAM 的时间线不是线性替代，而是几条能力逐步合流。2010s 的视觉预测与 latent dynamics 解决“动作之后会怎样”的基本问题；2020s 初的机器人 foundation policy 解决“跨任务和跨机器人如何输出动作”的问题；随后 interactive video model 和 physical AI pretraining 提供更大的世界先验；近年的 WAM 工作把这些线索合成 architecture choices：显式未来是否还需要在线生成，动作 token 是否应和视觉 token 共享上下文，object memory 是否需要进入 future representation，benchmark 是否要从预测质量推进到 embodied utility。这个演化视角使读者看到继承关系，而不是只看到新名称。

4. Architecture taxonomy: Cascaded WAM and Joint WAM

WAM 架构最自然的一级划分是 Cascaded 与 Joint。Cascaded WAM 先构造未来、rollout、latent transition 或辅助 world model，再把它接给 planner、policy 或训练目标。Joint WAM 则把 action 和 world representation 放入统一模型、统一 token stream 或统一 latent alignment 中，使动作生成与未来预测在同一建模过程内耦合。这个 taxonomy 比 system-node taxonomy 更贴近论文写法：很多论文首先声明的是“先预测再控制”还是“动作-世界联合建模”，而不是先声明自己属于 data engine 或 controller interface。

4.1 Cascaded WAM: explicit future then action

Cascaded WAM 的经典形式是 explicit future then action。Deep Visual Foresight 给定候选动作序列预测未来图像，再通过视觉目标选择动作，属于像素级未来作为 planning substrate 的早期范式 [p008]。latent imagination 方法把未来从像素转到 latent space，降低 rollout 成本，并把 world model 与 actor-critic 或 planning 连接 [p001] [p003]。在 WAM 语境中，这类架构的优势是可解释性和诊断性：模型可以把“为什么这个动作合理”部分转化为“这个动作会让未来状态如何变化”。

显式未来也带来误差传播。像素预测若追求视觉真实感，可能牺牲与控制相关的细节；latent 预测若只服务 reward/value，可能缺少物体级或语言级可解释性。Cosmos、V-JEPA 2 和相关 video foundation model 提供了更强的预测表示，但它们是否能直接成为机器人控制中的 WAM，还取决于 action conditioning、policy interface 和 evaluation protocol [p011] [p012]。因此，Cascaded WAM 的核心不是“能生成未来”，而是未来表示是否被动作选择、策略训练或失败诊断实际使用。

4.2 Cascaded WAM: implicit and latent alignment

第二类 Cascaded WAM 不一定在 test time 生成人类可看的未来，而是在训练阶段通过 future-aligned latent、dynamics prior 或 action-to-world prior 约束 policy。LaWAM 和 transferable dynamics prior 类工作把 action 后的世界变化压到 latent 表示或 dynamics prior 中，目标是让策略获得 dynamics-awareness，同时减少部署时的显式 rollout 成本 [p031] [p033]。Fast-WAM 则把这一点作为中心问题：WAM 是否必须在 test time 做 future imagination，还是可以把 future prediction 当成训练约束，部署时只保留更快的 policy pathway [p026]。

这类方法改变了评测重点。若模型不在部署时输出未来，视觉 fidelity 指标就不是主指标；更合适的是 policy utility、latency、ablation between training-time imagination and no-imagination、以及 failure cases 中的 dynamics sensitivity。它也改变了论文关系：explicit visual foresight 强调可检查未来，training-only WAM 强调把未来知识蒸馏进动作模型，两者的分歧是 inference cost 与 diagnostic transparency 的交换，而不是谁更“像 WAM”。

4.3 Joint WAM: autoregressive action-world modeling

Joint WAM 的代表路径是 autoregressive action-world modeling。WorldVLA 把 action 与 world representation 放进序列化建模框架，使模型可以在 token level 上处理观察、语言、动作和未来之间的依赖 [p023]。Unified Video Action Model 也体现了 video 与 action 的统一建模倾向，把未来视觉和动作生成放到更紧耦合的 architecture 中 [p022]。这类方法的吸引力在于，它减少了 cascaded pipeline 中“world model 输出什么、controller 如何读”的接口缝隙。

Joint 也有代价。统一序列会让训练数据格式、tokenization、context length、动作频率和视觉压缩成为同一个工程问题。FAST 和 action tokenization 相关工作说明动作表示本身足以改变 VLA 的扩展性；当 action token 和 world token 进入同一 stream 时，token budget 与 temporal abstraction 会直接影响可建模的 horizon [p021]。因此，Joint WAM 的核心 bottleneck 往往不是概念上能否联合，而是数据、token、频率、延迟和评测之间是否协调。

4.4 Joint WAM: diffusion and unified/multi-stream modeling

另一个 Joint 方向来自 diffusion、flow 和 unified/multi-stream architectures。Diffusion Policy 和 pi0 说明生成式 action distribution 可以服务 visuomotor policy，尤其在多峰动作和连续控制上具备优势 [p020] [p019]。把这类 action generation 与 future/world representation 对齐，形成的是一种不一定自回归、但仍然 joint 的 WAM：动作轨迹和未来变化通过同一 denoising、flow 或 latent alignment 过程协同生成。

unified-stream 与 multi-stream 的选择是 Joint WAM 中的关键分叉。unified-stream 把语言、视觉、动作和未来放到同一序列，便于共享 scaling law 与 token machinery；multi-stream 保留不同模态的专用编码器、dynamics head 或 action head，便于处理不同频率和控制精度。World-Language-Action、GigaWorld-Policy、MotuBrain 等工作体现了这类取舍：它们都在追求 action-centered 或 world-action integrated modeling，但对动作接口、训练效率和 deployment pathway 给出不同答案 [p027] [p028] [p032]。

架构 taxonomy 的结论是：Cascaded/Joint 是一级骨架，显式/隐式未来、自回归/diffusion、unified/multi-stream 是二级分支。system-object 节点可用于诊断每个分支内部的接口质量，却不应取代这个主骨架。这样组织后，读者能更快判断一篇新 WAM 论文是在替代 cascaded rollout、改进 joint tokenization、降低 deployment latency，还是引入新的 data/evaluation substrate。

因此，架构章节的任务不是给每篇论文贴一个永久标签，而是解释设计空间中的移动方向。一个方法可能从 Cascaded 起步，在训练中使用显式 future loss，部署时却走向 distilled policy；另一个方法可能采用 Joint token stream，但在 controller 端仍然保留独立 action head。taxonomy 应允许这种混合，同时保持一级问题清晰：未来和动作是在 pipeline 中先后连接，还是在模型内部共同生成、共同对齐、共同评测。

如果把这套 taxonomy 画成 roadmap，左侧应是两条输入河流：world-model roots 提供 latent dynamics、visual foresight 和 video prediction，VLA roots 提供 language-conditioned action decoding、cross-embodiment data 和 action tokenization。中间分叉成 Cascaded 与 Joint：Cascaded 分支继续分成 explicit video future、latent future、training-only future constraint；Joint 分支继续分成 autoregressive token stream、diffusion/flow action-world generation、unified-stream 与 multi-stream。右侧不是单一输出，而是 data ecosystem、evaluation protocols 和 deployment interface 三个检查点。这样一张图能防止读者把 WAM 理解为单个模型结构，而是看到从数据到表示、从表示到动作、从动作到评测的整条技术路径。

这个 roadmap 也给 paper-to-paper relation 一个自然位置。Deep Visual Foresight 位于 Cascaded explicit future 的根部；World Models 和 Dreamer 位于 latent imagination 的根部；Open X-Embodiment、pi0 和 FAST 位于 VLA/action-interface 根部；UVA 和 WorldVLA 位于 Joint WAM 的代表节点；Fast-WAM 位于 training-only 与 test-time imagination 的分界；OA-WAM 与 Mem-World 位于 object/memory diagnostic branch；SC3-Eval、WorldArena 和 ACWM-Phys 位于 evaluation branch。这样的关系图比按年份排序更有用，因为它说明每篇论文改变了哪条边、哪个瓶颈、哪个评测层。

因此，architecture taxonomy 最终服务的是设计选择。若研究目标是可解释规划，Cascaded explicit future 仍有优势；若目标是低延迟部署，latent 或 training-only future 更合适；若目标是把 VLA scaling 和 world modeling 合并，Joint autoregressive 或 diffusion/flow family 更自然；若目标是 manipulation 中的持久对象，object-addressable 或 memory-augmented representation 需要进入二级设计。这个章节给出的不是封闭分类，而是一组可操作的问题：未来在哪里表示，动作如何进入模型，controller 如何消费表示，评测如何验证这条 action-world coupling。

5. Training data ecosystem

WAM 的数据生态比普通 VLA 更复杂，因为它不仅需要 observation-action 对，还需要未来可预测性、动作后状态变化、跨时间一致性和任务目标。第一类数据是机器人遥操作与真实机器人 logs。Open X-Embodiment 是这一类的代表，它把多机器人、多任务、多机构数据合并，支持通用 robot policy 的训练 [p016]。对 WAM 来说，这类数据的价值在于提供 action-conditioned transitions；限制是动作空间、控制频率、摄像头视角和成功标签异质，future representation 难以统一。

第二类数据是 UMI-style 或 human demonstration 风格的数据，即人类手持、可穿戴、第一人称或低成本装置收集的演示。它们能扩展场景和物体覆盖，但动作标签和机器人可执行动作之间存在 gap。WAM 如果使用这类数据，需要解决 human video future 与 robot action interface 的对齐问题：模型可以学到物理常识和 object affordance，但未必直接学到机器人控制所需的 torque、gripper 或 end-effector trajectory。这个 gap 也是 Cascaded 与 Joint 架构的共同压力点。

第三类数据是仿真与生成式数字孪生。CALVIN、LIBERO、RoboTwin 等 benchmark 和环境为 long-horizon manipulation、lifelong learning、dual-arm tasks 提供可控任务结构 [p040] [p041]。仿真的优势是可以系统性构造 counterfactual action、失败轨迹和评测协议；限制是视觉、接触动力学和真实部署之间存在 domain gap。WAM 使用仿真时，最适合研究 action-world consistency、diagnostic ablation 和 policy utility，而不应把仿真成功直接等同于真实泛化。

第四类数据是互联网规模视频、egocentric video 和 physical AI foundation-model pretraining。Cosmos、Genie、iVideoGPT、V-JEPA 2 等方向给 WAM 提供了大规模 world prior 和 interactive video prior [p009] [p010] [p011] [p012]。这些数据提升的是世界变化、物体持久性、视觉动态和常识性 temporal structure；缺失的是机器人动作标签。因此，数据生态中的核心问题不是“数据越大越好”，而是 action labels、future supervision、language grounding 和 deployment feedback 如何组合。

表 1 汇总了主要数据来源和它们对 WAM 的贡献。它的读法不是给数据源排序，而是检查一篇 WAM 论文到底从哪里获得 action-world alignment。

这个数据视角也解释了为什么 WAM 评测不能只看视频预测或 success rate。若训练数据主要来自互联网视频，模型可能有强 world prior 但弱 action grounding；若主要来自机器人 logs，模型可能有强动作可执行性但弱开放世界覆盖；若主要来自仿真，模型可能有好 ablation 但需要真实迁移验证。因此，数据生态应成为 WAM 综述的独立章节，而不是散落在方法描述里的附注。

数据生态还影响论文之间的可比性。两篇 WAM 论文即使都报告 manipulation success，也可能因为数据源不同而回答不同问题：一个依赖真实机器人 logs，主要检验可执行 action-conditioned transitions；另一个依赖大规模视频预训练，主要检验 world prior 是否能迁移到机器人；第三个依赖仿真 counterfactual，主要检验物理一致性和 ablation。若综述不把这些差异显式化，读者会误以为架构差异解释了全部性能差异。实际上，WAM 的能力经常由 architecture、data mixture 和 evaluation protocol 共同决定。

因此，未来 WAM 论文应报告更结构化的数据卡片：动作标签来源、控制频率、观察视角、语言标注方式、future supervision 类型、仿真或真实比例、失败轨迹是否保留、以及跨 embodiment 归一化策略。这样的数据卡片不是行政附录，而是解释 WAM 机制结论的必要上下文。没有它，Cascaded 与 Joint 的比较很容易被数据覆盖率、任务难度或控制器差异掩盖。

6. Evaluation protocols

WAM 的评测至少有五层。第一层是 visual fidelity：生成未来是否清晰、稳定、符合视觉统计。这对 video WAM 必要，但远远不够。第二层是 physical commonsense：物体是否保持持久性，接触、遮挡、重力、碰撞和可达性是否合理。ACWM-Phys 和 SC3-Eval 代表了把 action-conditioned video/world model 放到物理交互和 self-consistency 检查中的方向 [p036] [p038]。

第三层是 action plausibility：模型给出的动作或 action-conditioned rollout 是否可执行，是否尊重机器人 kinematics、gripper 状态、控制频率和任务约束。FAST、Diffusion Policy、pi0 和 VLA action-token 研究提醒我们，动作表示会直接影响模型能否表达复杂轨迹 [p020] [p021] [p019]。第四层是 policy utility：WAM 是否提升下游成功率、sample efficiency、long-horizon robustness 或失败恢复。CALVIN、LIBERO、RoboTwin 和 WorldArena 这类 benchmark 把任务成功、知识迁移和 embodied utility 放进评测中心 [p040] [p041] [p037]。

第五层是 latency and deployment：WAM 是否需要 test-time rollout，rollout 的 horizon 多长，是否能在真实控制频率下运行，是否需要大模型在线生成视频。Fast-WAM 对这个问题的贡献在于，它把 training-time future modeling 与 inference-time future imagination 分开讨论 [p026]。这使评测协议必须报告 latency、compute、failure recovery 和 ablation，而不只是最终 success rate。

一个最低限度的 minimum evaluation recipe 应包含五个显式元素：protocol 说明任务、输入输出、控制频率和是否在线 rollout；metric 说明视觉质量、物理一致性、动作可行、策略收益或延迟中的哪一项被测量；baseline 至少包含 reactive VLA、no-WAM policy、non-action-conditioned world model 或 oracle/privileged future 中的合适对照；ablation/control 应隔离 future branch、action representation、data source、context length 或 rollout horizon；confounder 则要报告 perception error、controller clipping、dataset prior、sim-real gap 和硬件 latency。因此，评测章节给出的不是一个单分数排行榜，而是一份 evaluation recipe：每个强结论都必须能回指到 protocol、metric、baseline、ablation/control 和 confounder。

这个 matrix 的启示是：WAM 论文的强结论必须说明自己在哪一层成立。一个模型可以在 visual fidelity 上强，但 policy utility 未被验证；也可以在 policy utility 上有效，却没有提供可检查未来；还可以在训练时利用 world-action consistency，但部署时不输出 future。成熟 WAM 评测需要跨层组合，而不是把单一 benchmark 分数当作全局答案。

评测协议还需要处理 negative controls。对于 Cascaded WAM，至少应比较 no-future policy、oracle or privileged future、wrong-action future、以及不同 rollout horizon；对于 Joint WAM，至少应比较 action token ablation、world token ablation、context length、以及仅 VLA 或仅 video pretraining 的替代模型。对于 training-only WAM，还要区分 future loss 带来的 representation improvement 与额外数据、额外 compute 或更强 backbone 带来的收益。没有这些 negative controls，WAM 的贡献会被“更大模型”或“更多数据”解释掉。

部署评测同样不可省略。真实机器人系统关心的是控制频率、失败恢复、在线 memory、动作安全边界和人类监督成本。一个需要长时间视频 rollout 的模型可能适合离线计划或高层 deliberation，却不适合低层闭环控制；一个 distilled WAM policy 可能适合快速动作，却不容易解释失败原因。因此，evaluation chapter 必须把 latency 与 interpretability 放在同一个讨论框架里，而不是把它们当作工程细节。

从设计指导看，评测结果应回流到 architecture choice。如果失败主要来自 contact physics，优先修复 action-conditioned physical representation，而不是扩大语言模型；如果失败主要来自 long-horizon subgoal drift，优先修复 future abstraction、memory 和 controller interface；如果失败主要来自动作不可执行，优先修复 action tokenization、trajectory parameterization 或 low-level controller；如果失败主要来自延迟，优先考虑 training-only WAM、distillation 或短 horizon latent future。这样的 evaluation-to-design loop 是 WAM 和普通视频生成评测的区别：评测不只是排名，而是告诉系统应该在哪个接口上改。

因此，一个成熟 WAM benchmark suite 应同时保留小型诊断任务和真实任务。小型诊断任务负责隔离物体持久性、接触、遮挡、动作可行性和 uncertainty；真实任务负责检查这些能力是否转化为 policy utility。只有两者结合，才能避免 benchmark 过窄或过宽。过窄的 benchmark 会奖励特定物理 probe，过宽的 benchmark 又会把 WAM 能力和 perception、language prior、controller strength 混在一起。protocol matrix 的目的就是在两者之间建立可解释的桥。

7. System interfaces as cross-cutting diagnostic lens

系统接口仍然重要，只是不应作为文章主目录。把它放在 Cascaded/Joint taxonomy 之后，反而更有解释力。第一类接口是 representation：未来以像素、latent、object state、token stream 还是 memory slot 表达。pixel future 适合 human inspection，latent future 适合低延迟，object-addressable representation 适合 manipulation 中的持久物体关系，token stream 适合与 VLA scaling 合并 [p030] [p031] [p023]。

第二类接口是 dynamics/update：模型如何把 action 后的世界变化写入未来表示。classic latent dynamics、action-conditioned video prediction、JEPA-style predictive representation、diffusion/flow denoising 和 autoregressive token update 都是不同答案 [p003] [p008] [p012] [p020] [p023]。这个接口决定模型擅长短期接触、长期一致性还是高层语义变化。

第三类接口是 action decoding：动作是连续控制、离散 token、chunk、skill、language-like command 还是 flow trajectory。FAST、Diffusion Policy、pi0 与 WorldVLA 分别显示 action representation 对 scaling、multimodality 和 joint modeling 的影响 [p020] [p021] [p019] [p023]。第四类接口是 controller interface：WAM 输出被 planner、policy、critic、MPC、action decoder 或 training objective 如何使用。Cascaded WAM 最容易在这里暴露误差传播；Joint WAM 最容易在这里暴露 token budget 与 latency。

第五类接口是 memory/retrieval。Mem-World 和 object-addressable WAM 把长期物体状态、可检索历史或对象地址放进 action-world modeling，回应了 manipulation 中“物体被遮挡后仍然存在、被移动后状态改变”的问题 [p034] [p030]。第六类接口是 evaluation/uncertainty：模型是否报告未来不确定性，是否能区分多种可能结果，是否把不确定性传给 controller 或 evaluator。WorldArena、SC3-Eval 和 ACWM-Phys 表达了从 perception utility、self-consistency 到 physical interaction 的不同评测压力 [p037] [p036] [p038]。

这个 lens 的价值在于诊断，而不是取代 taxonomy。比如，WorldVLA 与 Unified Video Action Model 都属于 Joint WAM，但它们在 token stream、action interface 和 evaluation protocol 上的取舍不同；Fast-WAM 与 LaWAM 都在降低或重塑 rollout 负担，但一个突出 test-time imagination 问题，一个突出 latent dynamics-aware policy；OA-WAM 与 Mem-World 都强调持久对象和记忆，但一个偏 object addressing，一个偏 memory-augmented action-conditioned world model。系统接口把这些差异说清楚，Cascaded/Joint taxonomy 则告诉读者这些差异处在什么架构家族中。

因此，system-interface lens 更像一套诊断问卷。读一篇 WAM 论文时，先问它属于 Cascaded 还是 Joint，再问它的 future representation 是像素、latent、对象还是 token；它的 action interface 是连续控制、chunk、token、flow 还是 skill；它的 controller 如何消费 future；它是否有 memory；它如何表达 uncertainty；它的评测是否覆盖相应接口。这个顺序能避免目录被组件拆散，也能保留系统级分析的精度。

8. Applications and scenarios

WAM 最直接的应用是机器人 manipulation。抓取、推、拉、开关、倒液体、整理、双臂协作等任务都依赖 action 后物体状态的预测。OA-WAM、MotuBrain、Mem-World 与 ACWM-Phys 体现了这个场景对 object persistence、contact dynamics、action feasibility 和 failure recovery 的需求 [p030] [p028] [p034] [p038]。在这里，WAM 的收益往往来自对“动作后世界”的显式约束，而不是单纯更大的视觉语言模型。

第二类场景是 long-horizon language-conditioned policy。CALVIN 和 LIBERO 这样的任务强调多步指令、知识迁移、环境状态和长期成功 [p040] [p041]。WAM 在这里可以承担三个角色：为子目标选择提供 imagined future，为训练阶段提供 dynamics-aware supervision，为失败恢复提供可检查的 state transition。若 WAM 只提升短期动作质量，却不能改善 long-horizon consistency，那么它对这类场景的贡献有限。

第三类场景是 autonomous driving、navigation 和 interactive environments。GAIA-1、Genie、iVideoGPT 与 world model surveys 展示了 generative world modeling 在更开放环境中的潜力 [p009] [p010] [p046]。这类场景和机器人 manipulation 的差别在于动作接口和物理接触不完全相同：驾驶和导航更强调场景演化、agent interaction 和 policy evaluation；manipulation 更强调接触、可达性和 object state。WAM taxonomy 必须允许这些场景共享 action-world modeling 原理，同时保留不同的评测标准。

第四类场景是 foundation-model training substrate。WAM 可以不直接部署为 planner，而作为 policy 训练时的 auxiliary model、data generator、consistency regularizer 或 failure simulator。Fast-WAM、GigaWorld-Policy 和 training-only WAM 思路说明，WAM 的应用不一定发生在 inference loop 内 [p026] [p027]。这对实际系统尤其重要，因为真实机器人控制常受延迟限制，训练时强、部署时轻的设计可能比在线视频 imagination 更可行。

这些场景共同提示：应用章节不应只是罗列任务，而要把场景需求映射回 architecture 与 evaluation。manipulation 需要 object-level future 和 contact evaluation；long-horizon policy 需要 temporal consistency 和 benchmark protocols；driving/navigation 需要 multi-agent world evolution；training substrate 需要 efficiency 和 ablation。由此，WAM 的应用价值才能从“新模型能做什么”转向“哪种 WAM 适合哪种部署压力”。

应用还应反向约束 taxonomy。若目标是桌面 manipulation，object-addressable future、memory/retrieval 和 contact-sensitive evaluation 往往比开放视频生成更重要；若目标是 mobile robot navigation，scene dynamics、agent interaction 和 long-horizon uncertainty 更重要；若目标是 generalist robot policy training，数据覆盖、动作 tokenization 和 training-time efficiency 更重要。也就是说，Cascaded 与 Joint 并不是抽象分类练习，而是帮助读者把应用压力转化为 architecture selection：什么时候需要可检查 rollout，什么时候需要 unified stream，什么时候需要 distilled policy，什么时候需要 memory-augmented future。

这也解释了为什么 WAM 应用不宜只用“机器人控制”一词概括。控制任务的层级差异很大：low-level visuomotor control 需要高频动作和稳定闭环；mid-level manipulation 需要 object state 和 contact prediction；high-level task planning 需要语言目标、子目标和失败恢复；offline policy improvement 需要数据生成和 consistency regularization。每一层都可能使用 WAM，但对 future representation 的要求不同。成熟综述应帮助读者识别这种层级差异，而不是把所有应用放入同一个成功率表格。

9. Open challenges

第一个挑战是 definition drift。WAM 术语很容易被扩张成任何含动作的 world model 或任何含视频的 policy。本文的三条件定义可以减少漂移，但仍需要社区在 benchmark 和论文写作中明确报告：action 如何进入模型，future representation 是什么，它如何改变 policy、training 或 evaluation。否则，WAM 会失去区分力。

第二个挑战是 data alignment。互联网视频提供 world prior，机器人 logs 提供 action grounding，仿真提供 counterfactual control，human demonstrations 提供场景覆盖；但这些数据的动作语义、时间频率、视角和可执行性并不一致。WAM 需要更好的 data mixture accounting：模型到底从哪类数据学到物理常识，从哪类数据学到机器人动作，从哪类数据学到长期目标。没有这层说明，scale 本身无法解释模型能力。

第三个挑战是 evaluation mismatch。视觉真实、物理常识、动作可行、策略收益和部署成本常常不一致。一个模型能生成漂亮未来，不一定能提高 robot success；一个模型能提高 success，也可能只是因为 policy prior 或 controller clipping；一个模型训练时用 future loss，部署时不输出 future，不能用同一套可视化指标评价。因此，WAM benchmark 需要协议矩阵和 ablation matrix，而不是单分数排行榜。

第四个挑战是 latency and control frequency。真实机器人控制通常要求稳定、低延迟、可恢复。显式 future rollout 可能提升诊断性，却增加在线成本；Joint token stream 可能减少 pipeline mismatch，却增加 context 和 decoding 负担；training-only WAM 可能降低部署成本，却牺牲可检查未来。未来方法需要更透明地报告 compute、latency、horizon 和 failure recovery，而不是只报告离线指标。

第五个挑战是 uncertainty and branching futures。真实世界中同一动作可能产生多种未来，尤其在接触、滑动、遮挡和人机交互场景中。WAM 若只输出单一路径，controller 会过度相信一个可能错误的未来。diffusion、ensemble、latent stochasticity 和 uncertainty-aware evaluator 都可能缓解问题，但关键是把 uncertainty 传给 action selection，而不是只作为生成多样性的附带结果。

第六个挑战是 paper-to-paper synthesis。当前 WAM 论文发展很快，容易形成“每篇都是新系统”的景象。更有价值的问题是：哪篇工作继承了 visual foresight 的显式未来，哪篇把 VLA action tokenization 推入 joint world-action stream，哪篇把 test-time imagination 替换为 training-time constraint，哪篇把 object memory 或 benchmark utility 补上。综述和 benchmark 都应鼓励这种关系图，而不是只给方法命名。

第七个挑战是 standard reporting。WAM 论文应更一致地报告架构家族、future representation、动作接口、数据来源、训练目标、是否 test-time rollout、评测层级、延迟和 failure cases。当前很多工作各自强调亮点，导致读者难以判断两个系统到底差在 architecture、data、action representation 还是 evaluator。一个轻量但统一的 reporting checklist，会比单纯增加 benchmark 数量更能推动可累积比较。

因此，开放问题不只是“模型还不够强”，而是社区还缺少一套把方法、数据、评测和部署连接起来的共同语言。Cascaded/Joint taxonomy 可以提供第一层语言，system-interface lens 可以提供第二层诊断，protocol matrix 可以提供第三层证据约束。三者合在一起，才能让 WAM 从快速命名阶段进入稳定比较阶段。

10. Conclusion

WAM 的成熟综述应先像领域地图，再像系统审计。本文采用 Cascaded WAM 与 Joint WAM 作为 article spine，是因为这正对应社区中最原生的架构分歧：先生成或对齐未来再行动，还是把动作与世界放进统一建模过程。system-object 的七类接口没有被丢弃，而是被放到 taxonomy 之后，用于诊断每个架构家族的 representation、dynamics、action decoding、controller、memory 和 evaluation 设计。

这个重构带来的主要收益有三点。第一，WAM 与 VLA、world model、ACWM 和 video policy 的边界更清楚，避免把所有相邻工作都纳入同一概念。第二，数据生态和评测协议成为独立章节，使读者能判断一篇论文的能力来自 robot logs、human video、simulation 还是 world foundation pretraining，也能判断它的结论成立于 visual fidelity、physical commonsense、action plausibility、policy utility 还是 deployment cost。第三，paper-to-paper relation 更清晰：Deep Visual Foresight 与 latent imagination 解释 Cascaded roots，Unified Video Action Model 与 WorldVLA 解释 Joint turn，Fast-WAM 解释 training-time 与 inference-time imagination 的分离，OA-WAM 与 Mem-World 解释 object/memory pressure，WorldArena、SC3-Eval 和 ACWM-Phys 解释评测正在从视频质量走向 embodied utility。

未来的 WAM 研究如果要从概念热度走向可累积科学，需要同时报告架构位置、数据来源、接口设计、评测层级和部署成本。只有这样，WAM 才能成为连接世界理解与机器人行动的稳定模型族，而不是一个随论文命名漂移的宽泛标签。因此，一个高质量 WAM 综述也必须服务这个目标：用领域原生 taxonomy 帮读者定位方法，用证据约束强结论，用 cross-cutting lens 指出下一步系统设计和评测修复的方向。

最后，WAM 综述的质量还取决于它能否给未来论文提供写作模板。一篇新论文若提出 Cascaded WAM，应说明 future representation 的形式、rollout 是否在线、controller 如何读取未来、错误如何传播、与 no-future policy 的差别在哪里；若提出 Joint WAM，应说明 token 或 latent 共享机制、动作频率、context budget、world/action ablation 和 latency；若提出数据或 benchmark，应说明它测的是哪个 capability layer，不能支持哪些结论。这样的模板把综述从“总结已有论文”推进到“规范下一批论文如何可比较地写作和评测”。这也是本文从 system-node 主目录转向 community-native taxonomy 的根本原因。

在这个证据标准下，WAM 的论文关系也要重新读取：一篇工作若只改进视觉预测，只能支持 world-prior 或 physical-consistency 层面的结论；若同时提供 no-future baseline、action ablation 和 policy utility，它才更接近 WAM 机制贡献；若报告低延迟部署，则还需要说明 online rollout、distillation 或 training-only objective 如何改变控制接口。这个 science paradigm profile 把机器人和 ML systems 的证据规范合并起来，使 taxonomy 不只是概念地图，也成为判断 claim strength 的工具。

因此，本文最终给出的不是一个替代所有视角的单一框架，而是一个优先级顺序：先用社区原生 taxonomy 建立地图，再用数据生态解释能力来源，再用评测矩阵限定结论，最后用系统接口 lens 做诊断。这个顺序能让综述既像领域综述，也保留证据约束。

这种写法也给读者一个 practical reading protocol：遇到新 WAM 论文时，先定位 Cascaded 或 Joint，再检查数据来源和评测层级，最后追问系统接口是否支持论文声称的能力。若三步不能对齐，该论文的结论就应被收窄。
