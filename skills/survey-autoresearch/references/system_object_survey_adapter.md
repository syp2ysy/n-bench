# System-Object Survey Adapter

Use this reference when the topic names a system, architecture, memory, planner, world model, retrieval system, controller, interface, or comparable composed object.

## Default Node Families

Start node-card construction from these hypotheses, then revise from paper cards:

1. capture/input node;
2. representation node;
3. storage/state node;
4. retrieval/read node;
5. update/consolidation node;
6. controller/planner/action interface;
7. evaluation/ablation interface.

## Node Card Questions

For each node, record:

- why the node exists;
- what input it consumes;
- what output it produces;
- what design families instantiate it;
- which paper cards support each family;
- what fails if the node is weak;
- which benchmarks, ablations, or diagnostics reveal the failure;
- what remains a gap.

Tasks and benchmarks are evaluation settings for the system object. They should not become the default spine unless the user explicitly asks for a task or benchmark survey.
